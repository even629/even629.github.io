This article introduces the QEMU initialization process, focusing on the creation process of the RISC-V virt Machine. The article uses gdb to trace the source code in reverse, and based on the QOM mechanism, at class_init and instance_init to set breakpoints, observing that the main function first calls qemu_init and then calls qemu_create_machine to create the machine, then first creates the class and then instantiates the QObject. It then describes in detail the virt_machine_init function's functionality: creating CPU cores by cluster, initializing various devices, and generating a device tree (DTB) in memory for virt. The article also explains the loading timing of the OpenSBI firmware—after the entire virt Machine is ready, through the machine_done callback to call riscv_find_and_load_firmware to load the default firmware.
