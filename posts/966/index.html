Problem:

P966 Vowel Spell Checker

https://leetcode.cn/problems/vowel-spellchecker/description/?envType=daily-question&envId=2025-09-14

Initially used a brute-force search method, but it TLE’d, as follows

Using hash table lookup can reduce from O(n^2) to O(n), below is the officially recommended C++ implementation

Average time complexity

Operationunordered_setunordered_map
InsertO(1)O(1)
SearchO(1)O(1)
DeleteO(1)O(1)
  • Here O(1) is Average complexity, assuming the hash function distributes uniformly and collisions are few.
  • Main advantages:Faster than std::set/std::map (based on red-black trees), and the lookup of a red-black tree is O(log n).

Worst-case time complexity

  • In the worst case, if all elements are hashed to the same bucket (hash collision), it degenerates into a linked list,：
    • and lookup, insertion, and deletion all become O(n)。
  • C++ standard library implementations typically use buckets + linked lists (or red-black trees); when there are too many collisions, the linked list is converted to a red-black tree, thereby reducing the worst-case complexity:
    • After C++11, unordered_map/unordered_set’s single bucket linked list length exceeds a certain threshold (usually 8), it is converted to a red-black tree, ensuring the worst-case complexity is O(log n)。

Space complexity

  • Average O(n), storing the hash table and elements.
  • The hash table requires an extra bucket array, taking up extra space.
