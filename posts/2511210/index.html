This article introduces the basic concepts and implementation principles of the QEMU Object Model (QOM), analyzing its mechanism for implementing object-oriented features (inheritance, encapsulation, polymorphism) based on pure C language. Taking the edu device in QEMU version 10.1.2 as an example, the article explains the operation process of QOM in detail, including three stages: type registration, type initialization, and object initialization. In the type registration stage, device types are defined through TypeInfo, and with the help of the DECLARE_INSTANCE_CHECKER macro to achieve safe type conversion, and through DEFINE_TYPES and type_init macro to mount the type registration function into the module initialization linked list; before the main function is executed, the GCC constructor feature is used to automatically execute the registration, and then in main, through the module_call_init to uniformly call the registration function, completing the registration of TypeImpl in the global hash table. QOM

The full name of QOM is QEMU Object Model, which is an abstraction layer implemented by QEMU using object-oriented thinking, used to organize various components in QEMU (such as device emulation, backend component MemoryRegion, Machine, etc.). It is similar to C++ classes, but QOM is implemented in pure C language.

The object-oriented features supported by QOM include:Inheritance, encapsulation, polymorphism。

The operation process of QOM consists of three parts:

  • Type registration
  • Type initialization
  • Object initialization

Based on object-oriented modeling concepts, QEMU provides a highly formatted and templated hardware modeling process. For beginners, one only needs to master the commonly used basic interfaces of QOM to smoothly carry out modeling work without delving into the internal principles.

We need to understand three points:

  1. How the device model is defined;
  2. How devices are instantiated during the QEMU loading phase;
  3. How different devices are connected (communicate).

Type initialization

The registration of types has been completed previously; we have all QOM TypeImpls registered in the global hash table, but the initialization of the class (type) has not been completed.

Class initialization is completed through type_initialize(), the function’s input is a TypeImpl type pointer ti representing type information.

**type_initialize actually executes the class initialization logic,**while type_register_internal only creates TypeImpl and adds it to the global table.

Type hierarchy

As can be seen from type_initialize, the parent type is also initialized when a type is initialized. QOM implements a concept similar to inheritance in C++ through this hierarchy.

The following analysis is based on the edu device as an example:

The hierarchical relationship of this edu type:

From the perspective of data structures:

In the type initialization function type_initialize, the statement ti->class=g_malloc0(ti->class_size) allocates the class structure for the type, which actually represents the type’s information. It is similar to a class defined in C++.

class_size is a field of TypeImpl. If this type does not specify it, the parent class’s class_size will be used for initialization.

The edu device type itself does not define a class_size, so it inherits the parent class’s class_size, which issizeof(PCIDeviceClass)。

Summary

  1. First, each type specifies a TypeInfo to register into the system;
  2. Then, when the system runs initialization, it converts TypeInfo into TypeImpl and puts it into a hash table;
  3. The system will initialize each type in this hash table;
  4. Next, based on the QEMU command-line parameters, the corresponding instance objects are created.

Fill in the data content of EduState

Types and objects are linked together through the class field of Object:obj->class = type->class。

Hierarchical relationship of object types:

The object construction of QOM can be divided into 3 parts:

  1. Type registration, constructing a TypeImpl through TypeInfo and adding it to the global hash table, in main throughmodule_call_init()completed (the registration function itself is added to the linked list before main through the constructor mechanism);
  2. Type initialization is performed in main. The first two stages are global, and all compiled QOM objects will call them;
  3. Object construction, which constructs specific instance objects, will only create objects for devices specified on the command line.

Now the object has been constructed and its initialization completed, but the data content of EduState has not yet been populated.

Object’s properties

QOM implements class-based polymorphism similar to C++, an object according to the inheritance hierarchy, can be Object, DeviceState, PCIDevice, etc. In QOM, to facilitate the management of objects, it alsoadds properties to each type and object. Among them:

  1. Class properties exist in the properties field of ObjectClass and are constructed in type_initialize;
  2. Object properties exist in the properties field of Object, this field is constructed in object_initialize_with_type;

Both are a hash table(mapping from property name to ObjectProperty).
